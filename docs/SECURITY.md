# Security model and limits

UpdateDeck runs as the current user. It respects Windows elevation, organization policy, signature checks, authentication and agreements. There is no permanently elevated GUI/service, security bypass, arbitrary downloaded provider, vendor UI automation, or silently installed package manager.

## Trust boundaries

Registry and manifest fields are untrusted data. Exact subprocess arguments use `ProcessStartInfo.ArgumentList`, without a command shell. The fixed CIM hardware query is the only PowerShell probe. JSON/XML reads are bounded; XML external entities are prohibited. Static plugin PE parsing has depth/offset/count limits and never loads a DLL. Optional portable scans exclude reparse paths and entire-drive roots.

WinGet execution requires a Windows-trusted Microsoft App Installer CLI, matching executable resources, reviewed source export, exact package ID/version/scope/architecture and fresh unchanged installation identity. Unknown identity, version/channel, pins, process state or policy defers work. No force, hash/security bypass, agreement acceptance or automatic restart is used. WinGet retains its normal installer applicability/integrity checks. Its pin database is inspected read-only and held against write/delete before provider reads; unsupported or damaged storage is preserved. Unknown pin output disables updates. Known cached pins remain holds until fresh verification.

The narrow official Notepad++ fallback requires a signed existing application, no established manager ownership, verified pin state and unique scope/architecture registration. Its official HTTPS metadata must identify one exact architecture asset with strong hash and bounded size. Every redirect is restricted. Downloaded payload hash, Windows signer and embedded version are checked while holding a deny-write/delete handle until completion. Uncertain monitoring retains its payload protection until the monitor completes, or until UpdateDeck exits if completion cannot be established. Pins and machine/application state are checked again before interactive launch. The installer still requires ordinary license/elevation interaction. A separate installed-file check determines verification. No binary is trusted merely because a URL contains a publisher's name.

Reviewed vendor handoffs use fixed exact official URLs or known executable locations with Windows trust and expected signer checks immediately before launch. No undocumented switches drive vendor upgrades. A validation-to-open race remains possible for a local user able to replace trusted files; UpdateDeck is not a security sandbox for installers or a defense against an already privileged attacker. No driver, firmware, game content, project dependency, browser profile, preset, sample library, license or personal document is changed by discovery.

## Persistence and interruption

SQLite transactions use FULL synchronization and a rollback journal. Every pending operation is persisted before installation; write failure prevents new work. Monitoring uncertainty, reboot boundaries and exceptions stop following installers. Pausing/cancelling/closing does not kill an active installer or restart Windows. A six-hour monitor limit records uncertainty. Exact process identity records that the parent command ended; an unknown child may remain. Only explicit user inspection clears that hold, and a separate fresh installed-version check is still required. An unverified target after command completion also stops later installers.

Corrupt databases are preserved before replacement. Corrupt policy/history payloads are retained for recovery; installations pause and uncertain history creates a hold. Future schema versions are not rewritten. Switching from an unavailable portable store to local fallback storage always pauses installations and automatic handoffs; a different local policy cannot silently authorize work. The notice requires review of policy and unfinished installers from the original location. Failed drives and power loss remain possible; portable users should back up Data before moving media. There is no guaranteed rollback or restore-point recovery.

Finished history is bounded to 2,000 records; all pending, active, unverified and inspection-held records survive pruning, including oversized queues. Logs rotate around 2 MB plus one prior file and redact the current profile prefix. GUI diagnostic export omits installation paths and raw process output. Inventory/database content naturally includes local software and paths. Command-line diagnostic reports contain paths and are intended for local inspection. Exports contain no collected passwords, credentials or license keys; review software history before sharing. Migration manifests have strict size/depth/item/type checks and exclude paths; metadata previews query only selected public package IDs, never install anything or import policy. No telemetry or automatic report upload exists. Normal catalog/publisher checks and explicitly opened official guidance contact their respective services.

## Artifact validation

Release/source validation reads bounded decompressed content, checks actual versus declared length and CRC-32, and rejects unsafe Windows paths, case aliases, file/directory collisions, links, ambiguous JSON and unexpected payloads. Source indexes must cover every file exactly with matching spelling and per-file hashes. Release validation records every portable payload hash in addition to native PE, runtime and signing checks. These checks establish consistency and extractability; unsigned checksums cannot establish publisher authenticity.

## Distribution status

These artifacts are unsigned development previews. SHA-256 files detect changes relative to a trusted copy but do not authenticate a publisher. SmartScreen, certificate or organization restrictions must not be bypassed. Real SignTool hooks sign all four first-party EXE/DLL files and setup, timestamp and verify the expected certificate; no signing key is embedded. A signed uninstaller and controlled publication remain production considerations.

No first-party UpdateDeck release feed exists. Self-update is not operational. A future implementation needs publisher-controlled HTTPS, signed metadata, pinned hash/architecture/version, trusted signer validation, staged out-of-process replacement, settings preservation and recovery. For now close active work and use the matching installer. No self-signed trust claim or rollback claim is made.

Clean-machine Windows 10/11, actual ARM64 hardware, restricted-account/proxy/managed-PC, accessibility, storage fault and isolated real third-party update tests remain release gates. Process/restart/disk safeguards reduce operational risk but cannot guarantee every publisher installer's compatibility.
